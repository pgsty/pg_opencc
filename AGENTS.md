# Agent notes for pg_opencc

- Package `pg_opencc`, extension `opencc`, fixed schema `opencc`. PostgreSQL 14 – 18.
- `vendor/opencc` is an unmodified, trimmed OpenCC release. Do not edit it by
  hand. Re-vendor it with `tools/vendor-opencc.sh` and record the tag, commit
  and tarball SHA-256 in `vendor/README.md`.
- `src/opencc_core.cpp` is the only code that touches OpenCC. Every exported
  function catches all exceptions, including `opencc::Exception`, which does
  not derive from `std::exception`. It never calls PostgreSQL. Keep it that way:
  no `palloc`, `ereport` or `elog` in C++.
- `src/opencc_pg.c` is the fmgr layer. Do not hold engine-owned pointers
  across another engine call, and free `ocpg_table` results in `PG_FINALLY`.
- Conversion functions are `IMMUTABLE`. Anything that can change results
  without a new extension version (user dictionaries, runtime configs) must be
  `STABLE` and live behind a different function name.
- `test/sql/opencc_upstream.sql` is generated by `tools/gen_upstream_test.py`;
  regenerate it rather than editing it.
- Verify with `make && make install && make installcheck` on a UTF8 cluster.
  Review `build/test/results/*.out` before copying them to `test/expected/`.
- Never commit `build/`, compiled objects, `.so`/`.dylib`, or downloaded
  tarballs. Check `git status` and staged file sizes before committing.
